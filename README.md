# Форма регистрации — учебный проект для семинара

Рабочая форма регистрации (телефон + пароль + подтверждение пароля) без сборки, чистый HTML/CSS/JS. Открывается прямо в браузере файлом `index.html`, никакой установки не требуется.

## Как использовать на занятии

1. Залейте этот проект в `main` — это ЭТАЛОННАЯ рабочая версия без багов.
2. Создайте 4 ветки от `main`, в каждой внесите один точечный баг (см. ниже) — это будут стартовые ветки для команд.
3. На занятии каждая команда получает свою ветку, копию репозитория (fork) или доступ на редактирование, и работает с ИИ, чтобы найти и исправить баг.
4. Каждая команда открывает Pull Request в `main`.
5. Вы по очереди мёржите PR, обновляете открытый `index.html` (или деплой) и показываете исправление на экране.

## Инструкция по багам для каждой ветки

### bug/phone — Команда 1: баг в валидации телефона

В файле `script.js` в функции `validatePhone` изменить:
```js
const isValidLength = digitsOnly.length === 11;
```
на:
```js
const isValidLength = digitsOnly.length >= 9;
```
Эффект: форма будет принимать заведомо короткие/неполные номера как валидные.

### bug/password — Команда 2: баг в проверке надёжности пароля

В файле `script.js` в функции `isPasswordValid` изменить:
```js
return getPasswordStrength(value) >= 2 && value.length >= 8;
```
на:
```js
return value.length >= 8;
```
Эффект: индикатор силы пароля показывает "слабый", но кнопка всё равно активна и форма принимает пароль вида `aaaaaaaa` как надёжный.

### bug/confirm-password — Команда 3: баг в сравнении паролей

В файле `script.js` в функции `doPasswordsMatch` изменить:
```js
return password === confirm && confirm.length > 0;
```
на:
```js
return password.toLowerCase() === confirm.toLowerCase() && confirm.length > 0;
```
Эффект: форма считает пароли `Qwerty123` и `qwerty123` совпадающими, хотя они разные по регистру — тонкая логическая ошибка, которую не видно на глаз.

### bug/submit-button — Команда 4: баг в блокировке кнопки

В файле `script.js` в функции `updateSubmitButtonState` изменить:
```js
submitBtn.disabled = !isFormValid();
```
на:
```js
submitBtn.disabled = false;
```
Эффект: кнопка "Зарегистрироваться" всегда активна, даже если поля не прошли валидацию — пользователь может отправить невалидную форму.

## Структура проекта

```
signup-form-workshop/
├── index.html      — разметка формы
├── style.css       — стили
├── script.js       — вся логика валидации (4 независимые функции для 4 багов)
└── README.md       — этот файл
```

Функции валидации физически разделены (`validatePhone`, `isPasswordValid`, `doPasswordsMatch`, `updateSubmitButtonState`), поэтому баги в разных ветках не пересекаются по коду — мёрдж всех 4 Pull Request в `main` должен проходить без конфликтов.
